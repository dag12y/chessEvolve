# ChessEvolve: Verified Self-Learning & Knowledge Distillation for Chess Move Ranking

**ChessEvolve** is a reproducible educational research project investigating recursive self-learning, automated regression-testing gates, and model compression via knowledge distillation for chess candidate-move ranking. Designed to execute entirely on a commodity **CPU** without GPUs, the project uses bounded evaluations from Stockfish as external reference supervision.

> **Project Scope:** ChessEvolve is an architectural demonstration of recursive improvement and distillation. It ranks legal candidate moves generated by `python-chess`; it is **not** designed or claimed to rival Stockfish.

---

## 1. Research Questions & Core Findings

1. **Does bounded self-learning improve a teacher ranker on held-out positions?**  
   *Finding:* Not automatically. In Milestone 3, fine-tuning on high-uncertainty positions degraded development regret from 22.2 cp to 26.1 cp ($\Delta = -3.9\text{ cp}$).
2. **How does an automated acceptance gate handle regressions?**  
   *Finding:* The gate rejected the degraded candidate checkpoint and automatically rolled back to the baseline teacher, preserving system stability.
3. **Does soft-target distillation outperform hard-label training?**  
   *Finding:* Both student variants learned competitive ranking behaviors on development data, while soft-target distillation produced exceptionally smooth loss curves ($\sim 0.0018$ loss).
4. **What computational trade-offs exist between teacher and student?**  
   *Finding:* Distillation compressed the teacher from **136,065 parameters to 29,889 parameters (-78.0%)**, reduced checkpoint storage from **535.2 KiB to 120.1 KiB (-77.6%)**, and accelerated CPU inference from **0.120 ms to 0.076 ms/position (~1.55× speedup)**.
5. **Sample Size Notice:** Current development and final-test evaluation splits contain 3 positions each to guarantee sub-second bounded CPU execution. Results represent verified architectural benchmarks rather than generalized chess strength.

## 3. Technology Stack & Installation

### Requirements
- Python 3.10+ (tested on Python 3.14)
- Stockfish UCI engine executable
- Linux / macOS / Windows (CPU only; no GPU required)

### Setup Virtual Environment
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

### Stockfish Engine Verification
ChessEvolve bundles a Linux x86_64 universal Stockfish binary at `tools/stockfish/stockfish/stockfish-linux-x86-64-universal`. You can verify engine responsiveness via:
```bash
python3 -c "
from pathlib import Path
from chessevolve.engine import StockfishAdapter, EngineSettings
engine_path = Path('tools/stockfish/stockfish/stockfish-linux-x86-64-universal')
with StockfishAdapter(engine_path) as sf:
    print('Stockfish version:', sf.version())
"
```

## 4. End-to-End Reproduction Workflow

Every stage uses real CLI scripts with deterministic configurations.

### Step 1: Run Full Test Suite
Run all 163 unit tests across splitting, encoding, engine adapters, training, self-learning, distillation, and evaluation:
```bash
pytest
```

### Step 2: Train Baseline Teacher (M2)
Trains a 2-layer MLP ranker (136k parameters) supervised by Stockfish evaluations:
```bash
python3 scripts/train_baseline.py \
    --seed 0 \
    --epochs 3 \
    --lr 0.001 \
    --batch-size 4 \
    --hidden-dim 128 \
    --num-games 10 \
    --max-plies 12 \
    --engine-depth 4 \
    --output-dir experiments/results/medium
```
*Outputs:* Checkpoints `best.pt`, `final.pt`, `history.json`, `split_info.json`.

### Step 3: Run Verified Self-Learning Loop (M3)
Executes active position selection, bounded feedback, verification, candidate fine-tuning, and acceptance gating:
```bash
python3 scripts/run_self_learning.py \
    --baseline-checkpoint experiments/results/medium/best.pt \
    --output-dir experiments/results/sl_round1 \
    --num-candidate-positions 6 \
    --selection-policy uncertainty \
    --engine-depth 4 \
    --fine-tune-epochs 2 \
    --gate-min-regret-reduction 0.0 \
    --round 1 \
    --seed 42
```
*Outputs:* `decision.json` (REJECT decision), `retained.pt` (preserved baseline), `candidate.pt` (audit checkpoint), `round_summary.json`.

### Step 4: Run Knowledge Distillation Multi-Seed Training (M4)
Trains compact 1-layer students (30k parameters) using hard labels and soft teacher targets:
```bash
python3 scripts/run_distillation.py \
    --checkpoint experiments/results/sl_round1/retained.pt \
    --dataset experiments/results/m4_data/datasets/train_records.jsonl \
    --manifest experiments/results/m4_data/datasets/manifest.json \
    --output-dir experiments/results/m4_smoke \
    --epochs 2 \
    --batch-size 4 \
    --temperature 2.0 \
    --hidden-dim 32 \
    --num-hidden-layers 1 \
    --seed 0 \
    --seed 1
```
*Outputs:* Checkpoints `hard_seed0.pt`, `distilled_seed0.pt`, `hard_seed1.pt`, `distilled_seed1.pt`, and `summary.json`.

### Step 5: Run Comprehensive Evaluation & Benchmark (M5)

#### Development Evaluation
```bash
python3 scripts/evaluate_models.py \
    --split dev \
    --manifest experiments/results/m4_data/datasets/manifest.json \
    --output-dir experiments/results/m5_dev
```

#### Final-Test Isolated Evaluation
```bash
python3 scripts/evaluate_models.py \
    --split test \
    --manifest experiments/results/m4_data/datasets/manifest.json \
    --output-dir experiments/results/m5_test
```
*Outputs in each directory:*
- `evaluation_results_<split>.json`: Complete machine-readable metadata, SHA-256 hashes, metrics, and parameters.
- `evaluation_results_<split>.csv`: Tabular results table.
- `regret_by_model_<split>.png`: Mean engine-score regret comparison chart (centipawns, lower is better).
- `top1_agreement_by_model_<split>.png`: Top-1 reference agreement comparison chart (%, higher is better).

## 7. Limitations & Honest Assessment

- **Automated Rollback Works:** Recursive self-learning poses genuine degradation risk; the automated acceptance gate proved vital by rejecting the degraded candidate.
- **Evaluation Sample Size:** The current held-out evaluation sets comprise 3 positions each to respect strict CPU execution budgets. This limits statistical generalization across deep opening/endgame theory.
- **Engine Horizon:** Bounded search depth (2–4) introduces tactical noise into reference centipawns.
- **Model Task:** The model evaluates legal candidate moves presented to it; it does not replace a full tree search engine.
